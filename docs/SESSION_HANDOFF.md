## 2. What was verified, and from where

The documentation hosts in `Claude.md` (kubejs.com, curseforge.com, the
tensura wikis, modrinth, archive.org) are blocked from the dev environment.
`raw.githubusercontent.com` and GitHub page views are reachable, so
everything below was read from source.

### TensurJS (mod id `tensura_kubejs`, by AQZL) — from the `TensurJS-main/` source on `main`
This is the KubeJS addon actually installed (`tensura_kubejs-1.0.0.0.jar`),
not the abandoned CurseForge "Tensura TR Javascript". Wiki:
https://github.com/AQZL/TensurJS/wiki (unreachable from here; the source is
the ground truth).
- Registry: `StartupEvents.registry(TensuraKubeJS.SKILL_REGISTRY, event => ...)`.
  `SKILL_REGISTRY` is `manascore:skills`. The plugin registers a *default*
  builder type, so it must be `event.create('ns:id')` with **no** second
  argument; `event.create(id, 'extra')` throws `Unknown type 'extra'`
  (that was why the skills never appeared). The category is set with
  `.type('extra' | 'common' | 'intrinsic' | 'unique' | 'ultimate' | 'resistance')`.
- Builder (`KubeJSSkillBuilder`): `name`, `description`, `icon('ns:skill/x')`
  (expands to `ns:textures/skill/x.png`), `type`, `modes`, `mode(..)`,
  `maxHeldTime`, `maxMastery`, `startingSkill`, `heldAttribute`,
  `canInteract`, `canActivate`, `canBeToggled(bool | cb)`, `canTick(bool | cb)`,
  `canScroll`, `canIgnoreCooldown`, `isMastered(cb)`, `onToggleOn`, `onToggleOff`,
  `onTick`, `onPressed`, `onHeld`, `onRelease`, `onScroll`, `onLearn`, `onForget`,
  `onMastered`, `onBeingDamaged`, `onDamageEntity`, `onTakenDamage`, `onDeath`.
  There is no EP-requirement or learning-cost hook; acquisition uses
  Tensura's defaults.
- `SkillContext` (all callbacks): `instance`, `entity`, `keyNumber`, `mode`,
  `heldTicks`, `delta`, `isToggled()`, `mastery()`, `setMastery()`,
  `cooldown()`, `setCooldown(seconds)`, `consumeMagicule(amount) -> boolean`
  (via `EnergyHelper.isOutOfMagiculeConsuming`), `spawnEntity(id)`, `tell(msg)`.
- `SkillDamageContext` (`onBeingDamaged`, `onDamageEntity`, `onTakenDamage`):
  `source`, `target`, `amount()`, `setAmount(f)`. Callbacks return a boolean;
  `false` cancels. In `onBeingDamaged` the amount is a copy (cancel only);
  `onTakenDamage` carries the real `Changeable`, so rescaling goes there.
- Callback exceptions are caught and logged by TensurJS as
  `Error in KubeJS skill callback`; look for that in `logs/latest.log`.
- Also available: `TensuraKubeJS.modifySkill('tensura:x')` overrides for
  existing skills (icon, cooldown, every callback above), race registry
  (`TensuraKubeJS.RACE_REGISTRY`), and elemental spirit helpers.

### ManasCore 1.21.1 (`ManasMods/ManasCore`, branch `1.21.1/minh`)
- Skill registry id: `manascore:skills` (`skill.impl.SkillRegistry`).
- `io.github.manasmods.manascore.skill.api.SkillAPI`:
  `getSkillRegistry()` (Architectury `Registrar<ManasSkill>`: `get`, `contains`,
  `getIds`), `getSkillRegistryKey()`, `getSkillsFrom(LivingEntity)` (never
  null, returns `Skills.EMPTY` when the storage is missing).
- `Skills.getSkill(ResourceLocation)` / `getSkill(ManasSkill)` return
  `Optional<ManasSkillInstance>`; `getLearnedSkills()`; `learnSkill(ResourceLocation)`.
- `ManasSkillInstance`: `isToggled()`, `setToggled()`, `canBeToggled(entity)`,
  `isMastered(entity)`, `getMastery()`, `getOrCreateTag()`, `markDirty()`,
  `onToggleOff(entity)`, `getSkill()`, `getSkillId()`.
- `ManasSkill` hooks: `onBeingDamaged(instance, entity, DamageSource, float)
  -> boolean` (false cancels; amount read-only) and `onTakenDamage(instance,
  owner, DamageSource, Changeable<Float>) -> boolean`.

### Legendary Survival Overhaul (`sfiomn/LegendarySurvivalOverhaul`)
The GitHub `1.21.1` branch still holds the 1.20.1 Forge 2.3.x code; the
CurseForge `1.21.1-2.4` jar is NeoForge and its source is not published.
Public API package names are assumed unchanged.
- `api.bodydamage.BodyDamageUtil` (static): `healBodyPart(player, part, float)`,
  `hurtBodyPart`, `applyHealingTimeBodyPart`, `getHealthRatio(player, part)`,
  `getMaxHealth(player, part)`. No static current-health getter (use
  ratio * max) and no static max-health setter.
- `api.bodydamage.BodyPartEnum`: `HEAD, RIGHT_ARM, LEFT_ARM, CHEST, RIGHT_LEG,
  RIGHT_FOOT, LEFT_LEG, LEFT_FOOT`.
- `IBodyDamageCapability` (via `util.CapabilityUtil.getBodyDamageCapability`
  in 2.3): `getBodyPartDamage`, `getBodyPartMaxHealth`, `setBodyPartDamage`,
  `setBodyPartMaxHealth`, `heal`, `hurt`.
- Limb max health already tracks the player's max health when config
  `body-parts-health / "Body Part Health Mode"` is `DYNAMIC` (the default);
  the script-side limb scaling was removed for that reason.
- `api.temperature.TemperatureEnum`: `FROSTBITE 0-10, COLD 10-16, NORMAL 16-24,
  HOT 24-30, HEAT_STROKE 30-40`; optimal body temperature is 20.
- `api.temperature.TemperatureUtil` (static): `getWorldTemperature(level, pos)`,
  `getTemperatureEnum(float)`, resistance modifiers. Body temperature lives on
  `ITemperatureCapability.getTemperatureLevel()/setTemperatureLevel(float)`
  (`CapabilityUtil.getTempCapability(player)` in 2.3).
- `api.thirst.ThirstUtil` (static): `takeDrink(player, int hydration, float saturation)`.
  Hydration level lives on `IThirstCapability.getHydrationLevel()` etc.
  (`CapabilityUtil.getThirstCapability(player)` in 2.3).
- Effects (`registry.MobEffectRegistry`): `thirst`, `hydration_fill`,
  `hot_food`, `hot_drink`, `cold_food`, `cold_drink`, `heat_resistance`,
  `cold_resistance`, `frostbite`, `cold_hunger`, `heat_stroke`, `heat_thirst`,
  `cold_immunity`, `heat_immunity`, `temperature_immunity`, `painkiller`,
  `painkiller_addiction`, `hard_falling`, `vulnerability`, `headache`,
  `recovery`. No `parasites`, `bleeding` or `fracture` effect: dirty water
  applies `thirst`; a limb at 0 HP is "broken" and inflicts the
  `hard_falling` / `vulnerability` / `headache` maluses.
- Damage type msgIds: `legendarysurvivaloverhaul.hyperthermia`,
  `.hypothermia`, `.dehydration`.

### KubeJS 2101 (`KubeJS-Mods/KubeJS`, branch `2101`)
- `StartupEvents.registry(<registry id>, ...)`; `PlayerEvents.tick` (common);
  `ItemEvents.foodEaten` (common, `event.entity` / `event.item`, no `event.player`);
  `ServerEvents.commandRegistry` (`event.commands`, `event.arguments`,
  `Arguments.GREEDY_STRING.create(event)` / `.getResult(ctx, name)`).
- No `scheduleInTicks` on the server in 2101 (`setTimeout` exists).
- `EntityPotionEffectsJS`: `add(holder, duration, amplifier, ambient, particles)`,
  `isActive(holder)`; effect id strings are wrapped to holders. Removal is
  vanilla `entity.removeEffect(holder)`.
- `Registry.of('minecraft:mob_effect').contains(id)`; no `Registry.MOB_EFFECT`.
- No `entity.age`; scripts use vanilla `tickCount`.
- Server scripts cannot assign to `global` (`'global' cannot be assigned to`
  and the whole file fails to load), and files do not share scope, so the
  diagnostics command lives inside the bridge file.
- **Rhino quirk:** `const` / `let` are function-scoped. A declaration inside a
  loop body throws `redeclaration of var` on the second iteration. Use `var`
  inside functions; top-level `const` is fine.
- `CommandSourceStack.sendSuccess(supplier, bool)` stringifies a JS arrow;
  use `sendSystemMessage(component)`.

## 4. Testing plan (in the modpack)

`tensura_lso_bridge.js` adds `/tensuralso` (op level 2): `status`,
`skills [filter]`, `learn <id>`, `limbs`, `temp`, `hurt <part> <hp>`,
`class <fully.qualified.Name>` (tests whether a Java class can be loaded).
Tensura's own command for granting skills is
`/tensura edit ability grant <player> <skill id>`.

1. Launch; run `/kubejs errors startup` and `/kubejs errors server` (empty =
   scripts loaded). `logs/kubejs/startup.log` should contain
   `[skills.js] registering custom skills` followed by `registered kubejs:...`.
   `/kubejs reload server-scripts` re-runs the server scripts; startup
   scripts need a restart.
2. Run `/tensuralso status` and fix every MISSING / NOT registered line.
3. `/tensura edit ability grant <you> kubejs:thermoregulation`, toggle it in
   the Tensura skill menu, stand in the Nether: magicules drop 2 per 5 s,
   `heat_resistance` / `cold_resistance` show under "LSO effects active",
   hyperthermia damage halves (or stops once mastered).
4. Grant `tensura:ultraspeed_regeneration`, toggle it, `/tensuralso hurt
   LEFT_ARM 6`, then `/tensuralso limbs` a few times: limb HP rises 2 HP/s.
5. Change race or max health; LSO's DYNAMIC mode re-splits limb maxes on its
   own (no script involved).
6. Drink dirty water with `kubejs:purification` toggled; the `thirst`
   effect disappears within a second.
7. Toggle `tensura:heat_resistance` on: `heat_resistance` appears under
   "effects applied by the bridge" and LSO heat-stroke damage is negated.
   Toggle it off: the effect is gone within one check (1 s). Nullification
   skills apply `heat_immunity` / `cold_immunity` instead.
